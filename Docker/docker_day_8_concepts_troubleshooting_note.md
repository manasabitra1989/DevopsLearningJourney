# DevOps Winter Arc - Day 08: Docker Fundamentals

## 1. Core Docker Concepts

### Image vs. Container
* **Image**: A static, read-only template that contains application code, libraries, dependencies, runtime, and the base operating system filesystem. Think of it as a blueprint or class.
* **Container**: A running, isolated process and execution environment instantiated directly from an image. Think of it as a live object created from that blueprint. Multiple containers can run simultaneously from a single image.

### `docker ps` vs. `docker ps -a`
* **`docker ps`**: Displays only actively running containers along with their status, mapped ports, and runtime IDs.
* **`docker ps -a`**: Displays all containers on the host, including those that are stopped, exited, or failed, allowing inspection of exit codes.

---

## 2. Primary Docker Commands

* **`docker run`**: Creates and starts a container instance from an image (pulls the image from Docker Hub automatically if not found locally).
* **`docker logs <container>`**: Retrieves the standard output (`stdout`) and standard error (`stderr`) streams generated by the container process.
* **`docker inspect <container>`**: Returns comprehensive, low-level JSON configuration details, including network settings, assigned IP addresses, environment variables, and storage volume bindings.
* **`docker stop <container>`**: Sends a graceful termination signal (`SIGTERM`) to halt the running container process cleanly.
* **`docker rm <container>`**: Removes a stopped container from the local host disk.
* **`docker image rm <image>`** (or `docker rmi`): Deletes a stored Docker image from the local machine.

---

## 3. Port Mapping Demystified

### `-p 8081:80`
* **Syntax**: `-p <Host_Port>:<Container_Port>`
* **Meaning**: Maps incoming network traffic on the host machine's port **8081** directly into the container's internal web server port **80**.
* **Flow**: Client Browser -> `http://localhost:8081` -> Host Port 8081 -> Container Port 80 -> Internal Nginx Service.

---

## 4. Dockerfile Directives

* **`FROM`**: Specifies the base or parent image to build upon (e.g., `FROM nginx:alpine`).
* **`COPY`**: Copies local files or directories from the build context on the host machine into the filesystem inside the container image (e.g., `COPY index.html /usr/share/nginx/html/index.html`).
* **`EXPOSE`**: Informs Docker that the container listens on the specified network ports at runtime. It serves primarily as documentation between the image author and the person running the container; it does not publish the port by itself.

---

## 5. Investigating Container & Port Issues

When a container fails to start, crashes, or encounters network errors:

1. **Check Process State**: Run `docker ps` to verify if the container is running, or `docker ps -a` to see if it exited and note its exit code.
2. **Inspect Application Logs**: Run `docker logs <container_name>` to view runtime application crash logs, missing file errors, or startup stack traces.
3. **Inspect Configuration**: Run `docker inspect <container_name>` to verify assigned network bindings, environment variables, and mount paths.
4. **Inspect Host Port Usage**: If Docker reports `port is already allocated`, identify the process holding the port using:
   ```bash
   sudo ss -tulpn | grep :<port>
   ```

## 6. Day 8 Troubleshooting Note

* **Problem**: 
  The container failed to start because the designated host network port was already occupied by an existing process.
* **Evidence**: 
  Executing `docker run` failed with the error:
  `Error response from daemon: ... Bind for 0.0.0.0:8081 failed: port is already allocated`
  Executing `docker ps` confirmed that an active container named `day8-web` was already bound to host port `8081` (`0.0.0.0:8081->80/tcp`).
* **Root Cause**: 
  Port collision. On a single network interface (`0.0.0.0`), two independent processes or containers cannot bind to the exact same host TCP port (`8081`) simultaneously.
* **Fix**: 
  Removed the conflicting container using `docker rm -f day8-web`, then relaunched the container mapped to an unoccupied host port (`8082`):
  ```bash
  docker run -d --name day8-web -p 8082:80 day8-web:1.0
  ```
* **Verification**: 
  Verified running state with `docker ps` (showing `0.0.0.0:8082->80/tcp`), and executed `curl http://localhost:8082` to confirm an HTTP 200 response displaying the custom `index.html` page.
